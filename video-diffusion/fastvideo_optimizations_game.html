1 Your GPU Has Two Memories

And one of them is dramatically slower than the other.

Before any optimization makes sense, you need to know the secret bottleneck of GPUs: data movement, not math. GPUs can do trillions of operations per second — but only if data is sitting close to the compute cores.

Every GPU has two key memory tiers:

  • SRAM (on-chip cache): tiny (~100KB per block), but blazingly fast.
  • HBM (off-chip "VRAM"): huge (40–80 GB), but ~10× slower.
Try it — load a matrix and watch the speed difference

This single fact — SRAM is fast, HBM is slow, SRAM is tiny — is the reason every optimization in this game exists. Memorize it. Tattoo it. Move on.

2 Pick Your Attention Backend

3 Flash Attention — Tiling The Beast

The default backend. How it pulls off "exact attention, half the memory, 2× the speed."

Standard attention has a fatal flaw: it materializes a full N × N matrix in HBM. For video, N can be 100,000+ tokens. That matrix doesn't fit, and even when it does, shoveling it between HBM ↔ SRAM dominates wall-clock time.

Flash Attention's trick: never materialize the full matrix. Process tiny tiles in SRAM, accumulate running stats, and only write the final output back. Watch it run:

Naïve vs Flash — race them
Naïve attention
Idle
Writes the full N×N to HBM. Memory explodes with sequence length.
Flash attention
Idle
Streams tiles through SRAM. Same output, O(N) memory, 2–4× faster.

The math trick that makes this work is "online softmax": as each tile streams in, you update a running max and running sum on the fly. You never need the whole row of scores at once.

Install it once and FastVideo will pick it automatically:

uv pip install flash-attn==2.7.4.post1 --no-build-isolation

On H100s (Hopper), compile FlashAttention 3 from source for an extra speedup.

4 Lower Precision = More Speed

Drop bits, gain throughput. Drag the slider.

Every number in the model is stored with some number of bits. Fewer bits = less data to move, faster math, smaller memory footprint. The cost is precision. Modern hardware (especially NVIDIA Hopper and Blackwell) accelerates aggressive low-bit formats.

BF16 / FP16 are the default — 16 bits per number, runs on any modern GPU.

FastVideo's low-precision attention backends:

  • SAGE_ATTN — INT8/FP8 quantized attention, 1.3–2× faster than FlashAttention 2.
  • SAGE_ATTN_THREE — FP4-aware, targets RTX 5090 / consumer Blackwell.
  • ATTN_QAT_INFER — 4-bit DiT + modified SageAttention 3. Hard-gates on sm_120 (RTX 5090).
  • FP4 Flash Attention 4 — official Blackwell datacenter path. Up to 1.31× kernel speedup over BF16, reaching 2018 TFLOPS.

FP4 FlashAttention 4 in code:

gen = VideoGenerator.from_pretrained("model-id", nvfp4_fa4=True)

Catch: incompatible with use_fsdp_inference=True. Cosine similarity vs BF16 ≈ 0.99.

5 torch.compile — Pay Once, Run Fast Forever

Compile the model graph. First run slow, every run after is faster.

By default, PyTorch is "eager" — it runs one operation at a time. torch.compile traces the model into a single graph and lets the Inductor compiler fuse ops, pick faster kernels, and skip Python overhead.

Enabling it:

generator = VideoGenerator.from_pretrained("model-id", enable_torch_compile=True)
Real measurement — Wan2.1-T2V-1.3B on A100-80GB (480×832, 81 frames, 50 steps)

Key rules:

  • Always discard the first generation when measuring — that one ate the compile cost.
  • The compiled graph is shape-specialized. Change resolution or frame count → it recompiles.
  • reduce-overhead mode (CUDA graphs) isn't supported end-to-end yet — stick with default Inductor mode.
  • Combined with quantized backends or FP4, validate output quality with MS-SSIM on your config.

6 Adaptive Guidance — Skip Half The Work

Classifier-free guidance does two forward passes per step. We can cache.

Classifier-free guidance (CFG) is how diffusion models follow a prompt. Each denoising step runs the DiT twice: once with the prompt (conditional), once without (unconditional). The model output is a mix of the two, controlled by a guidance scale.

Doing both passes every step costs 2× compute. The insight: after some point in the denoising schedule, the difference between conditional and unconditional outputs stops changing much. So we cache that difference and stop running the unconditional pass.

FastVideo exposes this via FASTVIDEO_CFG_GATE_STEP, a float in [0, 1]:

Memory cost: one extra model-output tensor per rank. Quality cost: scales with how aggressive the gate is.

7 The Benchmarking Lab

Combine options. Time them. Don't lie to yourself about warmup.

Optimization without measurement is gambling. FastVideo's docs codify a standard benchmarking methodology:

  1. Same prompt. Same seed. Same configuration.
  2. Discard the first generation. It pays one-time costs (CUDA init, compile, kernel autotune).
  3. Measure steady-state across a few runs.
for backend in ["TORCH_SDPA", "FLASH_ATTN", "SAGE_ATTN"]:
    os.environ["FASTVIDEO_ATTENTION_BACKEND"] = backend
    generator = VideoGenerator.from_pretrained("model-id")
    # warmup run (discard)
    generator.generate(prompt, seed=1024)
    # timed runs
    t = time_generation(generator, prompt, seed=1024)
