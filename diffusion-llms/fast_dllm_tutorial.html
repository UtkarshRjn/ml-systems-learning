1 The Big Picture

Imagine you're writing a sentence. Today's ChatGPT-style LLMs write one word at a time, left to right. After "The cat sat on the ___", they predict "mat".

But what if a model could fill in many blanks at once, like a crossword puzzle? That's the promise of Diffusion Language Models (Diffusion LLMs).

The pitch: Diffusion LLMs start with a sentence full of [MASK] tokens and progressively fill them in. Because they don't go left-to-right, they could (in theory) generate text much faster by predicting many tokens in parallel.

Companies like Mercury (1,000+ tokens/sec) and Google's Gemini Diffusion (1,400+ tokens/sec) have shown this is possible. But open-source diffusion LLMs are still slow. Why?

❌ Problem 1: No KV Cache

Standard LLMs reuse past computations through a KV cache. Diffusion LLMs use bidirectional attention, so they can't naively cache anything — every step recomputes everything.

❌ Problem 2: Parallelism breaks quality

If you predict many tokens at once, they don't "talk" to each other. The model might pick "high" and "house" independently — producing "high house" which makes no sense.

Fast-dLLM's contribution: Two simple, training-free fixes that together give up to 27.6× speedup with almost no accuracy loss.
  • Block-wise KV Cache — caches keys/values within fixed blocks, exploiting the fact that activations change very little between adjacent denoising steps.
  • Confidence-aware Parallel Decoding — only unmask tokens the model is highly confident about, avoiding the "high house" failure mode.

2 Background — Two Ways to Generate Text

Autoregressive (AR) Models — left to right

GPT, Llama, Claude — these all generate text token-by-token, conditioning on what came before:

$$p(x_1, x_2, \ldots, x_n) = \prod_{i=1}^{n} p(x_i \mid x_1, \ldots, x_{i-1})$$

The key trick is causal attention: when generating token $x_5$, the model only attends to $x_1, x_2, x_3, x_4$. So the keys $K$ and values $V$ for those earlier tokens never change — they can be cached.

Autoregressive generation: each new token only depends on previous tokens, so older K/V values stay fixed and can be cached.

Diffusion LLMs — fill in the blanks

Diffusion LLMs use a completely different paradigm. They start with a sequence of all [MASK] tokens and progressively "denoise" them — predicting which tokens should replace the masks over many steps.

Crucially, they use bidirectional attention — every token can attend to every other token. This makes them more powerful for some tasks (like infilling), but it also means the K and V values for a token depend on the entire sequence, including future positions. If we change any token, all K/V values in principle change.

Diffusion generation: tokens can be revealed in any order. Each step uses bidirectional attention over the whole sequence.

3 Masked Diffusion Models, Built Up From Zero

Before we can understand the speedups, let's understand exactly what a Masked Diffusion Model (MDM) is doing. We'll build it up gently.

The forward process: how training data is corrupted

Take a clean sentence $x_0$. Pick a "noise level" $t \in [0, 1]$. For each token, with probability $t$ we replace it with [MASK]; with probability $1-t$ we keep it.

Formally, for each token position $i$:

$$q_{t|0}(x_t^i \mid x_0^i) = \mathrm{Cat}\bigl(x_t^i;\; \underbrace{(1-t)\delta_{x_0^i}}_{\text{keep original}} + \underbrace{t\,\delta_{[\text{MASK}]}}_{\text{replace with MASK}}\bigr)$$

In words:
  • $t = 0$: no masking — sequence is the original $x_0$
  • $t = 1$: everything is masked
  • $t = 0.5$: each token has a 50/50 chance of being masked
Cat = Categorical distribution. $\delta_a$ is a one-hot ("all probability on $a$").

Interactive: try different masking levels

The reverse process: training the model to denoise

We train a neural network $p_\theta$ to predict the original token at each masked position, given the partially masked sequence. The training objective (an Evidence Lower Bound on the log-likelihood) is:

$$\mathcal{L}_{\text{MDM}} = \int_0^1 \frac{1}{t}\, \mathbb{E}_{q_{t|0}(x_t|x_0)} \Biggl[ \sum_{i:\, x_t^i = [\text{MASK}]} -\log p_\theta(x_0^i \mid x_t) \Biggr] dt$$

Plain English: sample a random noise level $t$, randomly mask the input, then ask the model to predict each masked token. Minimize the cross-entropy loss on those predictions. That's it.

Generation: undoing the noise step by step

To generate, we start at $t = 1$ (all masks) and work our way down to $t = 0$. At each step we go from noise level $t$ to a smaller level $s < t$, "unmasking" some tokens. The transition has three cases:

$$q_{s|t}(x_s^i \mid x_t) = \begin{cases} 1 & \text{if } x_t^i \neq [\text{MASK}] \text{ and } x_s^i = x_t^i \quad \text{(already revealed, stays)} \\ \frac{s}{t} & \text{if } x_t^i = [\text{MASK}] \text{ and } x_s^i = [\text{MASK}] \quad \text{(stays masked)} \\ \frac{t-s}{t}\, q_{0|t}(x_s^i \mid x_t) & \text{if } x_t^i = [\text{MASK}] \text{ and } x_s^i \neq [\text{MASK}] \quad \text{(reveal)} \end{cases}$$

The three cases broken down:
  1. Already revealed — keep it (probability 1).
  2. Still masked, stays masked — probability $s/t$ (the ratio of remaining noise).
  3. Still masked, gets revealed — probability $\tfrac{t-s}{t}$, and the chosen token comes from the model's predictive distribution $q_{0|t}$.

The model's prediction $q_{0|t}(x_s^i \mid x_t)$ is just the softmax output of the neural network for position $i$: "given the current partially masked sequence, what token belongs at position $i$?"

The slow path: if you only unmask one token per step, you need ~$L$ steps for a sequence of length $L$. For $L=1024$, that's 1024 forward passes through the model. Painful.

The fast (but broken) path: unmask many tokens per step using $\tau$-leaping. Fewer steps — but generation quality collapses. Why? That's the topic of Section 6.

4 Problem #1 — Why Diffusion LLMs Can't Cache

In autoregressive models, causal attention means K and V for past tokens never need to change. Cache once, reuse forever.

In diffusion LLMs, bidirectional attention means every token's K, V depend on every other token. If any token changes (e.g., a mask becomes "cat"), in principle, every K and V changes — so nothing can be cached.

✓ Autoregressive: caching is easy

K, V for past tokens are computed once. Token $i$'s attention only looks at tokens $1..i$. Past K, V never depend on the future.

✗ Diffusion: caching seems impossible

Token $i$'s K, V are produced by attention over the entire sequence, including masked positions. As masks become real tokens, every K, V technically shifts.

The key empirical observation

The paper plots the cosine similarity of K, V activations across denoising steps. Result: they barely change between adjacent steps within a small block of tokens.

Simulated K,V cosine similarity heatmap (each cell = similarity between two inference steps)

Cells near the diagonal (similar steps) are bright yellow ≈ 1.0. Conclusion: K/V activations at adjacent inference steps are nearly identical — we can approximately reuse them.
The opportunity: if K/V values change by less than ε between adjacent steps, we can cache them and accept a tiny approximation error in exchange for huge speed gains.

5 Solution #1 — Block-Wise KV Cache

The idea

Instead of caching everything forever (impossible) or nothing (slow), Fast-dLLM uses blocks:

  1. Divide the answer region into fixed-size blocks (typical block size = 32 tokens).
  2. Before starting a block, do one full forward pass and compute K, V for the entire sequence (prompt + all blocks).
  3. Inside the block, freeze the K, V for everything outside the block. Reuse them on every step.
  4. Once the block is done, recompute K, V for the next block and freeze again.

This is approximate (because the cached K, V are slightly stale), but the heatmap above shows the approximation is tiny.

PrefixCache vs DualCache

PrefixCache

Cache only the prefix: prompt + previously decoded blocks. The current block and future blocks (still mostly masks) are recomputed each step.

DualCache (Dual = both sides)

Cache both the prefix and the suffix (the still-masked tail). Why does this work? Because masked positions all look the same to the network in K-projection space, so their K, V also barely change. Even faster.

Why this is a free lunch: The cache update happens at the end of each block. Since you needed to do a forward pass anyway to decode the next position, the cache update is essentially zero overhead. You just save the K, V tensors during that pass.

6 Problem #2 — The Curse of Parallel Decoding

Even with KV cache, we're still doing one token per step. To get the big speedup, we need to unmask multiple tokens in parallel. But here's the catch...

An example: poker hands

"The list of poker hands that consist of two English words are: ___ ___."

Valid completions: "high card", "two pair", "full house", "straight flush".

If we decode the two blanks independently, the model knows position 1 ∈ {high, two, full, straight} and position 2 ∈ {card, pair, house, flush}. Both have probability ~25% over their own marginal.

Independent sampling might give us: "high house". The marginals are correct individually, but the joint distribution is not the product of marginals. There's a hidden correlation that gets destroyed.

Formal statement of the problem

For two masked positions $i, j$, the true distribution is the joint:

$$p(x_s^i, x_s^j \mid x_t) \neq p(x_s^i \mid x_t) \cdot p(x_s^j \mid x_t)$$

But parallel decoding samples from the product on the right (the "conditional independence" approximation). When tokens are correlated, this introduces errors.

This is why LLaDA "performs best when generating tokens one at a time" — sequential decoding doesn't make this independence assumption. The challenge: how can we go parallel without ruining quality?

The intuition behind Fast-dLLM's fix

Here's the key insight. Even though, in general, $p(x_i, x_j) \neq p(x_i) p(x_j)$, there's a special case where it's approximately true:

When the model is very confident about a token — say, $p(x_i = \text{cat}) > 0.99$ — the joint distribution effectively collapses to a single value at that position. The correlation with other tokens vanishes, because there's no uncertainty to correlate.

This motivates the next idea: only decode tokens in parallel when the model is highly confident about them.

7 Solution #2 — Confidence-Aware Parallel Decoding

The recipe

  1. At each diffusion step, run the model on the current (partially masked) sequence.
  2. For each masked position $i$, compute the confidence $c^i = \max_v p_\theta(x^i = v \mid x_t)$ — the maximum softmax probability across the vocabulary.
  3. Pick a threshold $\tau$ (typical value: 0.9).
  4. Unmask every token whose confidence exceeds $\tau$. The rest stay masked for now.
  5. Special case: if no token meets the threshold, just unmask the one with the highest confidence (to avoid an infinite loop).

Try it yourself

⬆️ Try lowering $\tau$. More tokens get unmasked per step (faster) but lower-confidence tokens may have dependencies, hurting quality. Higher $\tau$ → safer but slower.

Why this works mathematically

The paper proves that when token marginals are all high-confidence (close to 1), parallel decoding with the product-of-marginals approximation gives the same answer as sequential decoding with the true joint distribution. The next section explains this theorem.

8 The Theorem (Made Simple)

Setup

Let's set up the notation carefully:

  • $E$ = current evidence (the prompt + already-decoded tokens). It's the input "context".
  • $X = (X_{i_1}, \ldots, X_{i_n})$ = the $n$ masked positions we want to decode.
  • $p(X | E)$ = the true joint distribution over those $n$ tokens (what we'd want).
  • $q(X | E) = \prod_j p_j(X_{i_j} | E)$ = the product of marginals (what parallel decoding actually does).

Question: when does $\arg\max_z p(z | E) = \arg\max_z q(z | E)$? I.e., when does greedy parallel decoding produce the same answer as greedy joint decoding?

Theorem 1 — Equivalence under high confidence

Theorem (Wu et al. 2025): Suppose there exists a sequence $x^* = (x_{i_1}, \ldots, x_{i_n})$ such that for each $j \in \{1, \ldots, n\}$, the model is very confident: $$p_j(X_{i_j} = x_{i_j} \mid E) > 1 - \epsilon$$ Then if $(n+1)\epsilon \leq 1$ (equivalently, $\epsilon \leq \tfrac{1}{n+1}$): $$\arg\max_z p(z \mid E) = \arg\max_z q(z \mid E) = x^*$$

What this means in plain English

If for every position the model assigns more than $1 - \epsilon$ probability to some token, and we're trying to decode $n$ tokens in parallel, as long as $\epsilon \leq 1/(n+1)$, parallel and sequential decoding agree on the same answer.

Concrete example. Suppose we want to decode $n=4$ tokens. Then we need $\epsilon \leq 1/5 = 0.2$, i.e., confidence $\geq 0.8$ at every position. If all four tokens have softmax probability ≥ 0.8 for their top choice, parallel decoding is guaranteed to give the same greedy answer as sequential decoding. ✓

How confidence threshold maps to "how many tokens can I decode in parallel"

Formula: $n \leq \frac{1}{1-\tau} - 1$. At $\tau = 0.9$, you can safely decode up to 9 tokens at once. At $\tau = 0.99$, up to 99 tokens!

Why the bound is intuitive

The theorem proof shows that when each marginal puts $\geq 1 - \epsilon$ on its top token, the joint probability of the all-top combination $x^*$ is at least $1 - n\epsilon$. Meanwhile, any alternative joint has probability at most $\epsilon$ on at least one factor, so a careful counting argument gives the bound.

Bonus: divergence bounds

The paper also bounds how far the marginal product $q$ is from the joint $p$ in standard probability metrics:

Total Variation distance: $$D_{\text{TV}}(p, q) < \frac{3n-1}{2}\, \epsilon$$ $L_p$ distance: $$D_p(p, q) < ((n-1)^p + 2n)^{1/p}\, \epsilon$$ Forward KL divergence: $$D_{\text{KL}}(p \| q) < (n-1)\bigl(H_b(\epsilon) + \epsilon \ln(|\mathcal{V}| - 1)\bigr)$$ where $H_b(\epsilon) = -\epsilon \ln \epsilon - (1-\epsilon)\ln(1-\epsilon)$ is the binary entropy.

These bounds all go to 0 as $\epsilon \to 0$. So the higher the confidence, the more parallel we can safely go.

From theorem to algorithm: the factor-based strategy

Instead of a fixed threshold $\tau$, you can pick a factor hyperparameter $f$ and dynamically choose the largest $n$ such that $(n+1)(1 - c^{(n)}) < f$, where $c^{(n)}$ is the $n$-th highest confidence. This adapts the parallelism per step based on confidence levels.

9 Putting It Together — Algorithm 1

Here is the full algorithm — block-wise decoding with KV cache and confidence-aware parallel decoding:

Require: model p_θ, prompt p_0, answer length L, blocks K, block size B,
         steps per block T, threshold τ, use_DualCache, strategy, factor f

 1:  x ← [p_0; [MASK], ..., [MASK]]              # initialize all-masked answer
 2:  Initialize KV Cache (single or dual)         # // KV Cache init

 3:  for k = 1 to K do                            # loop over blocks
 4:      s ← |p_0| + (k - 1) · B
 5:      e ← |p_0| + k · B
 6:      for t = 1 to T do                        # denoising steps within block
 7:          if use_DualCache: run p_θ on x[s:e]   # only forward current block
              else:            run p_θ on x[s:]    # forward block + suffix
 8:          for each masked x^i: compute c^i = max_x p_θ(x^i | ·)
 9:          if strategy == threshold:
10:              Unmask all i in [s, e] with c^i ≥ τ
                  Always at least unmask argmax c^i
11:          else if strategy == factor:
12:              Sort c^i descending: (c^(1), c^(2), ...)
13:              Find largest n with (n+1)(1 - c^(n)) < f
14:              Unmask top-n tokens
15:          if all x[s:e] unmasked: break
16:      end for
17:      Update KV cache:                          # // cache update
            if DualCache: update prefix & suffix
            else:         update prefix only
18:  end for
19:  return x

Three loops in one picture

  • Outer loop (blocks): work from left to right through blocks.
  • Inner loop (steps): denoise within a block. Each step the cache is reused, no recomputation of outside-block K, V.
  • Per-step (selection): choose which tokens to unmask based on confidence.
How many forward passes are needed? (Click to expand)

Suppose answer length $L = 1024$, block size $B = 32$ (so $K = 32$ blocks), and threshold $\tau = 0.9$. Empirically, each block needs ~4–5 forward passes (not 32 — the confidence-aware step often unmasks several tokens per pass). Total: ~140 forward passes.

Vanilla LLaDA needs ~1024 forward passes (one token per step). So this is already a 7× reduction in steps, on top of the KV-cache speedup per step. That's where the 27.6× total comes from.

Sensitivity to hyperparameters

Threshold τ

The sweet spot is around τ = 0.9. Below 0.5 quality drops noticeably; above 0.95 you barely unmask multiple tokens per step (defeats the purpose).

Block size B

Optimal block size is around 32 tokens. Too small → too many cache refreshes (overhead). Too large → cache becomes stale, accuracy drops.

11 Summary & Key Takeaways

One-sentence summary: Fast-dLLM speeds up diffusion language models by 5–27× with two training-free tricks — block-wise approximate KV caching, and confidence-aware parallel decoding — backed by a theorem that high-confidence tokens can be safely decoded in parallel.

What to remember

  1. Diffusion LLMs ≠ Autoregressive LLMs. They generate by progressively unmasking, using bidirectional attention. This makes naive KV caching impossible.
  2. K, V activations are nearly identical across adjacent denoising steps. Empirical fact, exploited by block-wise caching with negligible loss.
  3. Parallel decoding breaks token dependencies. "high house" instead of "high card" — the product of marginals isn't the joint.
  4. High confidence ⇒ safe parallelism. Theorem 1 quantifies this: $\epsilon \leq 1/(n+1)$ guarantees greedy equivalence for $n$ parallel decodes.
  5. Empirical sweet spot: block size = 32, threshold τ = 0.9, DualCache enabled.

Limitations and open questions

  • The KV cache is approximate. There's a measurable (though small) accuracy gap on some tasks.
  • Greedy decoding is implicitly assumed by Theorem 1. Sampling diversity (temperature > 0) is less rigorously analyzed.
  • The block size and threshold are still hyperparameters — they're not adapted per task.
  • Whether the same tricks apply to discrete continuous-time diffusion models (SEDD-style) is not yet shown.
