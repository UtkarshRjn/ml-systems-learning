How DFlash Trains Its Draft Model from the Target Model

A walkthrough of the training recipe behind DFlash's block-diffusion speculative-decoding draft model — every design choice explained through one question: what will the draft model actually see at inference time?

Source: Jian Chen, Yesheng Liang, Zhijian Liu (UC San Diego). "DFlash: Block Diffusion for Flash Speculative Decoding." ICML 2026. arXiv:2602.06036 · GitHub · Project page. All facts, numbers, and hyperparameters below are taken directly from the paper (including its appendix); the training recipe is not yet in the public GitHub repo at the time of writing.

1. Why diffusion for drafting?

Speculative decoding speeds up a big target model M_t by having a small draft model M_d propose γ tokens per cycle, which the target then verifies in parallel. The average per-token latency is: 

L = (T_draft + T_verify) / τ          # τ = expected number of accepted tokens per cycle
speedup η = L_target / L

The catch: autoregressive draft models (EAGLE, Medusa, ...) generate their γ tokens one at a time, so drafting cost scales linearly with the speculation budget: 

T_draft (autoregressive) = γ · t_step        # grows with γ → forces very shallow draft models

A diffusion draft model instead fills an entire block of γ positions in a single parallel forward pass: 

T_draft (diffusion) = t_parallel              # ~constant — barely grows with γ
Because drafting cost no longer scales with block size, a diffusion drafter can afford to be deeper and more expressive without paying a latency tax. DFlash's core bet: use that extra capacity, fused tightly with the target model's own hidden features, to get long accepted spans and low drafting latency at the same time — something autoregressive drafters structurally can't do. Result: DFlash reports up to 6.1× lossless speedup, about 2.5× faster than EAGLE-3.

2. The draft model, just enough to understand training

DFlash's draft model is a small transformer stack (typically 5 layers, 8 for the Qwen3-Coder variant) with two unusual properties, both of which training has to be built around:

  • It has no embedding table and no LM head of its own — it reuses the target model's, frozen. It only ever operates in the target's vocabulary/representation space.
  • It doesn't just see the previous token — it's conditioned on fused hidden features from several target-model layers, injected directly into every draft layer's attention as extra Key/Value entries (not fed in as input embeddings, unlike EAGLE-3).

At inference, the draft model fills a whole block_size-token block (starting from one clean "bonus" token already verified by the target) in one forward pass, and the target verifies the entire block in parallel. That block-filling behavior is exactly what training has to teach.

3. The training pipeline, end to end

Every choice below exists to make a training example look exactly like what the draft model will see once it's deployed. Keep asking "what happens at inference?" and the training recipe stops looking arbitrary.
Curate self-distilled data. Take prompts from a large SFT-style mixture, but replace the dataset's original responses with responses generated by the frozen target model itself.
Extract & fuse target features. Run the clean (prompt + response) sequence through the frozen target model once; pull hidden states from 5 layers, concatenate and project them into one compact per-token "target context feature."
Sample anchors, build blocks. Randomly pick anchor positions in the response; each anchor becomes a clean bonus token, the next block_size − 1 positions become mask tokens the draft model must predict.
Pack many blocks into one training sequence. Concatenate blocks and train them jointly with a sparse attention mask: bidirectional inside a block, blocked across blocks.
Inject target features as KV, at every layer. The fused target feature is added as extra Key/Value entries to every draft transformer layer's self-attention — not fed in as an input token.
Weight the loss toward early block positions. Cross-entropy at each masked position is scaled by an exponentially decaying weight, since an early mistake invalidates every token after it under greedy acceptance.
Optimize only the small draft stack. Target model, embedding table, and LM head all stay frozen; only the draft transformer layers (and one small projection) are trained.

Step 1: Curate data via self-distillation

Training data is a ~800K-sample mixture drawn from the NVIDIA Nemotron Post-Training Dataset V2 and CodeAlpaca (the LLaMA-3.1 ablation instead uses UltraChat + ShareGPT, matching EAGLE-3's setup exactly for a fair comparison).

The subtle but important part: DFlash does not train on the dataset's original responses. For every prompt, the frozen target model generates its own response, and that becomes the training label. This closes the distribution gap between "what some other model/human said" and "what the target model actually tends to say" — the exact distribution the draft model needs to imitate to get long accepted spans.

Step 2: Extract and fuse target features

For each clean (prompt + response) sequence, the frozen target model runs once. Hidden states are pulled from 5 layers, uniformly spaced between the 2nd layer and the third-to-last layer (8 layers for Qwen3-Coder). They're concatenated per token and projected into one shared feature: 

H_t = RMSNorm( W_c · [ H⁽ˡ¹⁾ ; H⁽ˡ²⁾ ; H⁽ˡ³⁾ ; H⁽ˡ⁴⁾ ; H⁽ˡ⁵⁾ ] )   # W_c: D × 5D shared projection

H_t is the same for every draft layer — computed once, reused everywhere (§5 shows this scales acceptance length with draft depth far better than injecting once at the input, EAGLE-3 style, where the signal dilutes as it's carried through more layers).

This extraction can happen online (recomputed every training step) or offline (precomputed once and cached to disk, then loaded during draft optimization) — offline trades disk space for a much cheaper training loop, since the multi-billion-parameter target model doesn't need to run forward on every step.

Ablation check (paper Table 10): a 5-layer draft model trained without any target conditioning only reaches a modest 2–3× speedup. Feeding it the target's own hidden features is what turns "small transformer guessing blindly" into "small transformer riding on the target's internal representations" — this single choice is the biggest lever in the whole recipe.

Step 3: Sample anchors, build blocks

Standard block-diffusion training uniformly chops the response into fixed blocks. DFlash does something different, matched to speculative decoding: it randomly samples 512 anchor positions per training sequence (resampled every epoch). Each anchor is treated as the first, clean token of a block; the following block_size − 1 positions are replaced with a mask token, and the draft model is trained to predict them in parallel.

This exactly matches inference: the draft model always starts a block from one clean token — the "bonus token" the target model just verified in the previous cycle. Randomizing anchor positions also exposes the draft model to far more diverse target-context features per epoch than a fixed chopping would, which the paper finds meaningfully improves both acceptance length and speedup (Table 13: random anchors push MT-Bench speedup from 2.13× to 2.38×).

Step 4: Pack many blocks per training sequence

Sampling 512 anchors per sequence would be enormously wasteful if each block needed its own forward pass. Instead, all sampled blocks for a sequence are concatenated and trained jointly in one forward/backward pass, using a sparse attention mask built with FlexAttention: tokens attend bidirectionally within their own block and to the injected target feature, but attention across different blocks is disallowed — otherwise a block could "peek" at another block's answer key.

Step 5: Inject target features as KV, at every layer

Instead of fusing target features into the draft model's input embeddings once (the EAGLE-3 approach — where the signal dilutes as it passes through more draft layers), DFlash injects the same fused feature H_t as extra Key/Value entries at every draft layer's self-attention, alongside the draft tokens' own KV: 

Q_i =        W_i^Q · H_d                            # queries: from draft tokens only
K_i = concat( W_i^K · H_t ,  W_i^K · H_d )           # keys:    target feature  +  draft tokens
V_i = concat( W_i^V · H_t ,  W_i^V · H_d )           # values:  target feature  +  draft tokens

The target feature bypasses the draft model's own query projection, output projection, and FFN — it only ever serves as something for draft tokens to attend to. The extra parameters are tiny (just the shared projection W_c, tens of MB even for a 35B target model).

Step 6: Weight the loss toward early block positions

Not all predicted positions in a block matter equally. Because DFlash's acceptance rule is a greedy prefix match (candidate token t+1 must equal the target's own argmax at t+1, checked left to right), one wrong token early in the block throws away every correct token that comes after it. The loss reflects that asymmetry with an exponentially decaying per-position weight: 

w_k = exp( −(k − 1) / γ )                     # k = position within the block (1 = right after the anchor)
loss = Σ_k  w_k · CrossEntropy( draft_logits_k , target_token_k )

γ is set per block size: 7 for block size 16, 5 for block size 10, 4 for block size 8. The paper's ablation (Figure 5) shows this decay makes training converge faster and reach a higher final acceptance length than uniform weighting.

Step 7: Optimize only the small draft stack

The draft model shares the target model's token embedding layer and LM head — and keeps both frozen during training. So does the target model itself. Only the draft transformer layers (plus the small feature projection W_c) are updated.

This does two things at once: it forces the draft model to stay in the target's representation space (its output logits are directly comparable to the target's, by construction), and it keeps the trainable parameter count tiny — a few hundred million parameters at most, regardless of how large the target model is.
