State-Space Models, in Plain English

A friendly tutorial for an undergrad who already knows what a neural network and a Transformer are. No control theory background required.

1. The one-sentence pitch

A State-Space Model (SSM) is a neural network that reads a sequence one token at a time and keeps a small "memory" vector — called the state — that summarizes everything it has seen so far.

Imagine you're watching a movie and taking notes on a sticky note. You can't write down every frame, so each new scene you see, you update your sticky note: keep some old notes, add some new info, throw out the rest. At any moment, the sticky note is your state — a compressed summary of the whole movie so far. When someone asks "what's happening?", you read off your sticky note. That's an SSM.

2. Wait, isn't that just an RNN?

Yes — basically! An SSM is the great-grandchild of the RNN, with three big upgrades that make it work on modern GPUs and modern-scale data. If you understand RNNs, you understand 80% of SSMs already.

Here's an RNN in one line:

h_t = tanh( W · h_{t-1} + U · x_t )       # update memory
y_t = V · h_t                              # produce output

And here's an SSM in one line:

h_t = A · h_{t-1} + B · x_t              # update memory  (notice: NO tanh!)
y_t = C · h_t                              # produce output
The big difference: an SSM uses a linear update (no tanh, no sigmoid). That sounds like a downgrade — and it would be, if SSMs stopped there. But linearity is exactly what unlocks the cool tricks below. The non-linearity gets added back between SSM layers, like in a Transformer the non-linearity lives in the MLP between attention layers.

3. The four matrices: A, B, C, D

An SSM is defined by 4 matrices. They each have a job:

MatrixJobPlain English
Astate → state"How does my memory decay / mix when I move forward one step?"
Binput → state"How much of the new token gets written into memory?"
Cstate → output"How do I read out an answer from my memory?"
Dinput → output (skip)"A direct shortcut from input to output, skipping memory."

Putting them together:

h_t = A · h_{t-1} + B · x_t
y_t = C · h_t       + D · x_t
Back to the sticky-note movie analogy:
  • A = how much of your old notes you keep when you re-read them (do they fade? get reorganized?)
  • B = how aggressively you write down what's happening in the new scene
  • C = how you summarize your sticky note when someone asks "what's going on?"
  • D = "actually, just look at the current scene and ignore the notes" (a shortcut)

4. The magic trick: two modes, same model

Here's where SSMs get genuinely cool — and why they beat plain RNNs in practice. The same SSM can be computed in two completely different ways, depending on what you need:

Mode A: Recurrent mode (one step at a time)

h_0 = 0
for t in 1..N:
    h_t = A · h_{t-1} + B · x_t
    y_t = C · h_t

This is the RNN-style loop. Cheap at inference time: constant memory per token (you only keep h_t), and you generate token-by-token. Perfect for chatbots, autocomplete, real-time audio.

Mode B: Convolutional mode (whole sequence at once)

Because the update is linear, if you unroll the recursion you get: 

y_1 = C·B · x_1
y_2 = C·A·B · x_1 + C·B · x_2
y_3 = C·A²·B · x_1 + C·A·B · x_2 + C·B · x_3
...

Each output is a weighted sum of past inputs — that's literally a convolution with kernel K = (CB, CAB, CA²B, CA³B, …).

Convolutions can be computed in parallel for every token at once using FFTs. This is amazing for training: a GPU can crunch the entire sequence in one shot instead of looping like a sad RNN.

Train as a convolution (fast on GPUs, parallel). Run as a recurrence (cheap, streaming). Same exact math. This dual nature is the central magic of SSMs — RNNs can't do this because their tanh breaks the linearity.

6. SSM vs Transformer: the trade-off

Transformer (attention)SSM
How it remembers Stores every past token; can re-read any of them exactly Compresses everything into a fixed-size state vector
Cost per token (inference) Grows with sequence length (O(N)) Constant (O(1))
Cost to process whole sequence O(N²) — every token attends to every other O(N log N) via FFT, or O(N) recurrent
Best at Precise recall, copy/paste, in-context learning Long sequences, streaming, audio/DNA/time-series
Worst at Million-token contexts (gets really expensive) "Find the exact phone number from 10k tokens ago"
Transformer = a librarian who has every book on the shelf and can pull any page exactly. Slow on millions of books, but perfect recall.

SSM = a friend who watched the whole movie and remembers the gist. Fast and cheap to ask, but they might mix up which character said what in scene 14.

7. The SSM family tree (papers in your folder)

SSMs aren't a single model — they're a family that's been evolving fast. Here's the lineage:

  • 2021 S4 — first SSM that beat Transformers on long-range benchmarks. Introduced the special A matrix initialization (HiPPO) that lets the model remember thousands of steps back.
  • 2022 H3 (Hungry Hungry Hippos) — added a gating trick (two SSMs multiplied together) so SSMs could finally do language modeling competitively. → H3_HungryHungryHippos.pdf
  • 2023 Monarch Mixer (M2) — replaced the SSM convolution with structured "Monarch" matrices that map perfectly onto GPU matrix-multiply units. Sub-quadratic in both sequence length and model width. → MonarchMixer.pdf
  • 2023 FlashFFTConv — the FFT used by SSMs was slow on GPUs; this paper made it 7.9× faster, unlocking million-length sequences. → FlashFFTConv.pdf
  • 2023 Mamba — made the A, B, C matrices depend on the input itself (called "selective" SSM). Finally matched Transformer quality on language modeling.

9. TL;DR

An SSM = an RNN with a linear update. The linearity is the magic: it lets you train the model as a parallel convolution (fast on GPUs) but run it as a streaming recurrence (cheap at inference). The A matrix governs memory; B writes inputs to memory; C reads outputs from memory. Compared to Transformers: SSMs win on long sequences and streaming, lose on precise recall — which is exactly the gap H3, Mamba, and friends in your paper folder are trying to close.

1. Where does non-linearity come in?

The SSM recurrence h_t = A·h_{t-1} + B·x_t, y_t = C·h_t + D·x_t is purely linear. Stack ten of them with nothing else and they collapse into a single linear map. So where does the non-linearity actually come from?

Non-linearity is added around the SSM block, never inside the recurrence. The time loop stays linear on purpose — that's what unlocks the FFT/parallel-scan training trick.

The four sources

SourceWhere it livesNotes

MLP / FFN between blocksLinear → GELU → LinearSame as Transformer FFN
Input-dependent params (Mamba)A_t, B_t, C_t = f(x_t)Recurrence still linear given params, but x → params is non-linear. Breaks conv view; parallel scan still works.

                            ▲

2. RNN ≈ "Linear SSM"

Structurally identical, except for one σ:

Update rule
RNNh_t = σ(A·h_{t-1} + B·x_t), y_t = C·h_t
SSMh_t = A·h_{t-1} + B·x_t, y_t = C·h_t + D·x_t

So one SSM pass is the linear recurrence part of an RNN — same first-order Markovian state update, same h_{t-1} → h_t flow. The missing σ is the entire reason SSMs can train in parallel like Transformers while running in O(N) like RNNs.

RNN (with σ)SSM (linear)
Recurrent inference✅ O(N)✅ O(N)
Parallel training❌ — must unroll step-by-step✅ via convolution / parallel scan
Equivalent to a convolution?❌✅ K_t = C·Aᵗ·B
Long-range memorypoor (vanishing/exploding gradients)good (HiPPO init keeps Aᵗ stable)

3. RNN pass vs SSM pass — side by side

For input x = (x_1, x_2, x_3, x_4), hidden state h_0 = 0:

🔵 RNN pass (non-linear recurrence)

       x_1                x_2                x_3                x_4
        │                  │                  │                  │
        ▼                  ▼                  ▼                  ▼
  ┌──────────┐       ┌──────────┐       ┌──────────┐       ┌──────────┐
  │ A·h_0    │       │ A·h_1    │       │ A·h_2    │       │ A·h_3    │
  │ + B·x_1  │       │ + B·x_2  │       │ + B·x_3  │       │ + B·x_4  │
  │   σ(·)   │──h_1─▶│   σ(·)   │──h_2─▶│   σ(·)   │──h_3─▶│   σ(·)   │──h_4
  └────┬─────┘       └────┬─────┘       └────┬─────┘       └────┬─────┘
       │                  │                  │                  │
       ▼                  ▼                  ▼                  ▼
   y_1=C·h_1         y_2=C·h_2          y_3=C·h_3          y_4=C·h_4

⛔ Cannot parallelize: h_2 needs the result of σ(...) from step 1 before it can compute. One token at a time.

🟢 SSM pass — Mode 1: as a recurrence

       x_1                x_2                x_3                x_4
        │                  │                  │                  │
        ▼                  ▼                  ▼                  ▼
  ┌──────────┐       ┌──────────┐       ┌──────────┐       ┌──────────┐
  │ A·h_0    │       │ A·h_1    │       │ A·h_2    │       │ A·h_3    │
  │ + B·x_1  │──h_1─▶│ + B·x_2  │──h_2─▶│ + B·x_3  │──h_3─▶│ + B·x_4  │──h_4
  │ (no σ!)  │       │ (no σ!)  │       │ (no σ!)  │       │ (no σ!)  │
  └────┬─────┘       └────┬─────┘       └────┬─────┘       └────┬─────┘
       ▼                  ▼                  ▼                  ▼
   y_1=C·h_1+D·x_1   y_2=C·h_2+D·x_2   y_3=C·h_3+D·x_3   y_4=C·h_4+D·x_4

Same O(N) shape as RNN. Used at inference time — autoregressive decoding, constant memory.

🟢 SSM pass — Mode 2: as a convolution (the magic)

Because there's no σ, the recurrence unrolls symbolically:

h_1 = B·x_1
h_2 = A·B·x_1 + B·x_2
h_3 = A²·B·x_1 + A·B·x_2 + B·x_3
h_4 = A³·B·x_1 + A²·B·x_2 + A·B·x_3 + B·x_4

Then y_t = C·h_t + D·x_t becomes one big convolution:

y_t = (K * x)_t + D·x_t,   where  K = (C·B,  C·A·B,  C·A²·B,  C·A³·B,  …)

        x_1   x_2   x_3   x_4
         │     │     │     │
         └─────┴──┬──┴─────┘
                  ▼
           Conv with K
        (FFT in O(N log N))
                  │
        ┌─────┬───┴─┬─────┐
        ▼     ▼     ▼     ▼
       y_1   y_2   y_3   y_4   ← all computed in parallel
Mode 2 has zero non-linearity. K * x is linear, D·x is linear — the entire SSM block as a function of x is linear. That's exactly why it can be written as one fixed convolution kernel and FFT'd in parallel.

4. Stacking layers — where the σ goes

RNNs and SSMs both stack into multiple layers, but they place their non-linearities completely differently.

🔵 RNN: σ at every (layer, timestep) cell

   layer ℓ (one layer, four timesteps)

      x_1           x_2           x_3           x_4
       │             │             │             │
       ▼             ▼             ▼             ▼
    σ(...) ──h_1──▶ σ(...) ──h_2──▶ σ(...) ──h_3──▶ σ(...)
       ▲             ▲             ▲             ▲
       │             │             │             │
   non-linear    non-linear    non-linear    non-linear

Across L layers × N timesteps: L × N sequential non-linearities.

🟢 SSM: σ only between layers

   x_1   x_2   x_3   x_4
    │     │     │     │
    ▼     ▼     ▼     ▼
  ┌──────────────────────┐
  │   SSM (linear)       │  ← y = K * x + D·x
  │   shared A,B,C,D     │    no σ at any timestep
  └──────────────────────┘
    │     │     │     │
    ▼     ▼     ▼     ▼
  ╔══════════════════════╗
  ║   σ / GLU / MLP      ║  ← ONE non-linearity, pointwise across t
  ╚══════════════════════╝
    │     │     │     │
    ▼     ▼     ▼     ▼
   z_1   z_2   z_3   z_4   ──▶ next layer

Across L layers: just L non-linearities (depth only).

Non-linearities along timeNon-linearities along depthTotal per pass
RNN✅ one σ per timestep → N per layerimplicit (each cell already non-linear)L × N
SSM❌ zero — recurrence is purely linear✅ activation/MLP between layersL
The σ in the SSM block is still applied at every timestep — but it's the same σ, with no cross-time dependency, so all N applications run in parallel. In an RNN the σ at time t waits for the σ at time t-1. In an SSM the σ sits after the recurrence, not inside it.

5. Why shared A, B, C across time matters

"Recurrent" means weight-sharing along time, not depth:

                         depth (layers)
                              ▼
                     ┌────────────────────┐
                     │ Layer 1: A¹,B¹,C¹  │  ← own params
   time   ────▶      │ Layer 2: A²,B²,C²  │  ← different params
   (recurrent here)  │ Layer 3: A³,B³,C³  │  ← different params
                     └────────────────────┘

Within one SSM layer, (A, B, C, D) are reused at every timestep. That time-invariance is what makes the unrolled recurrence's coefficients depend only on the lag, not on absolute time:

y_t = Σ_k (C · Aᵏ · B) · x_{t-k}   +   D · x_t
                  ↑
         depends only on k → that's a convolution

If (A, B, C) varied per timestep, you'd get a different kernel at every position — no longer a convolution, no FFT trick.

AxisS4 / vanilla SSMMamba / S6
Across time (within one layer)✅ shared❌ varies: A_t, B_t, C_t = f(x_t)
Across layers❌ each layer has own params❌ each layer has own params
Conv view works?✅ fixed kernel → FFT❌ kernel changes per t
Fast training viaFFT (O(N log N))parallel scan (O(N))

Mamba breaks the time-invariance on purpose — letting the model "decide" how to update state per token recovers some of the expressiveness of an RNN's σ — and pays for it by switching from FFT to a parallel scan.

6. The punchline

The single design choice — keep the recurrence linear, push all non-linearity to the layer boundary — is what gives SSMs their dual nature:
  • Train in parallel like Transformers (FFT or parallel scan along time)
  • Run in O(N) like RNNs (the linear recurrence still holds at inference)

Mental model: 

RNN:   non-linearity scattered through the (time × depth) grid
SSM:   non-linearity only on the depth axis;
       time axis is pure linear algebra
